DAG Edge Management API

The DAG Edge Management API provides endpoints for managing connections (edges) between nodes in a DAG workflow.

Create Edge​

Endpoint: POST /orchestration/api/v1/dags/{dagId}/edges

Creates a connection between two nodes in the DAG.

Path Parameters​

ParameterTypeRequiredDescription
dagIdLongYesThe DAG ID

Request Body​

{
  "fromNodeId": 101,
  "toNodeId": 102,
  "metadata": {
    "condition": "success",
    "description": "Data flow from extraction to transformation"
  }
}

Response​

{
  "id": 201,
  "dagId": 1,
  "fromNodeId": 101,
  "toNodeId": 102,
  "metadata": {
    "condition": "success",
    "description": "Data flow from extraction to transformation"
  },
  "createdAt": "2024-01-15T10:40:00Z"
}

Example Request​

curl -X POST "https://api.saasxl.com/orchestration/api/v1/dags/1/edges" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "fromNodeId": 101,
    "toNodeId": 102,
    "metadata": {
      "condition": "success",
      "description": "Data flow from extraction to transformation"
    }
  }'

Update Edge​

Endpoint: PUT /orchestration/api/v1/dags/{dagId}/edges/{edgeId}

Updates an existing edge in the DAG.

Path Parameters​

ParameterTypeRequiredDescription
dagIdLongYesThe DAG ID
edgeIdLongYesThe edge ID

Request Body​

{
  "fromNodeId": 101,
  "toNodeId": 103,
  "metadata": {
    "condition": "success",
    "description": "Updated data flow path"
  }
}

Example Request​

curl -X PUT "https://api.saasxl.com/orchestration/api/v1/dags/1/edges/201" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "fromNodeId": 101,
    "toNodeId": 103,
    "metadata": {
      "condition": "success",
      "description": "Updated data flow path"
    }
  }'

Delete Edge​

Endpoint: DELETE /orchestration/api/v1/dags/{dagId}/edges/{edgeId}

Removes an edge from the DAG.

Path Parameters​

ParameterTypeRequiredDescription
dagIdLongYesThe DAG ID
edgeIdLongYesThe edge ID

Example Request​

curl -X DELETE "https://api.saasxl.com/orchestration/api/v1/dags/1/edges/201" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN"

Edge Metadata Guidelines​

Common Metadata Fields​

FieldTypeDescriptionExample
conditionStringExecution condition"success", "failure", "always"
descriptionStringHuman-readable description"Data flow from extraction to transformation"
priorityNumberEdge priority for parallel execution1, 2, 3
timeoutNumberEdge timeout in seconds300
retryPolicyObjectRetry configuration{"maxRetries": 3, "delay": 60}
dataMappingObjectData transformation rules{"sourceField": "targetField"}
validationObjectData validation rules{"required": ["field1", "field2"]}

Example Edge Creation with Full Metadata​

curl -X POST "https://api.saasxl.com/orchestration/api/v1/dags/1/edges" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "fromNodeId": 101,
    "toNodeId": 102,
    "metadata": {
      "condition": "success",
      "description": "Transfer extracted data to transformation pipeline",
      "priority": 1,
      "timeout": 300,
      "retryPolicy": {
        "maxRetries": 3,
        "delay": 60,
        "backoffMultiplier": 2
      },
      "dataMapping": {
        "sourceTable": "extracted_data",
        "targetTable": "transformed_data"
      },
      "validation": {
        "required": ["user_id", "timestamp"],
        "dataTypes": {
          "user_id": "integer",
          "timestamp": "datetime"
        }
      }
    }
  }'

Edge Types and Conditions​

Execution Conditions​

ConditionDescriptionUse Case
successExecute only if source node succeedsNormal data flow
failureExecute only if source node failsError handling
alwaysExecute regardless of source node statusCleanup operations
conditionalExecute based on custom logicBusiness rules

Conditional Edge Example​

{
  "fromNodeId": 101,
  "toNodeId": 102,
  "metadata": {
    "condition": "conditional",
    "expression": "data.recordCount > 1000",
    "description": "Only process if more than 1000 records"
  }
}

Edge Validation Rules​

Node Validation​

  • Both fromNodeId and toNodeId must exist in the DAG
  • Nodes must belong to the same DAG
  • Cannot create self-loops (fromNodeId ≠ toNodeId)

Acyclic Graph Validation​

  • Edges must not create circular dependencies
  • System validates DAG structure before allowing edge creation
  • Maximum path length: 50 nodes

Metadata Validation​

  • Metadata must be a valid JSON object
  • Maximum metadata size: 5KB
  • Reserved keys: id, dagId, fromNodeId, toNodeId, createdAt

Parallel Execution​

Edge Priority​

When multiple edges lead to the same target node, priority determines execution order:

{
  "fromNodeId": 101,
  "toNodeId": 103,
  "metadata": {
    "priority": 1,
    "description": "High priority path"
  }
}

Parallel Edge Example​

# Create parallel paths
curl -X POST "https://api.saasxl.com/orchestration/api/v1/dags/1/edges" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "fromNodeId": 101,
    "toNodeId": 102,
    "metadata": {
      "priority": 1,
      "description": "Primary data path"
    }
  }'

curl -X POST "https://api.saasxl.com/orchestration/api/v1/dags/1/edges" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "fromNodeId": 101,
    "toNodeId": 103,
    "metadata": {
      "priority": 2,
      "description": "Secondary data path"
    }
  }'

Failure Handling Example​

# Create failure handling edge
curl -X POST "https://api.saasxl.com/orchestration/api/v1/dags/1/edges" \

Edge Monitoring​

Edge Execution Status​

Edges can be monitored during DAG execution:

{
  "id": 201,
  "dagId": 1,
  "fromNodeId": 101,
  "toNodeId": 102,
  "status": "PENDING",
  "executionTime": "2024-01-15T10:45:00Z",
  "duration": 30,
  "metadata": {
    "condition": "success",
    "description": "Data flow from extraction to transformation"
  }
}

    "code": "CIRCULAR_DEPENDENCY",
