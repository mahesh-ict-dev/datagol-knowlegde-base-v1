Error Handling

This section describes the error handling patterns and common error responses for the Orchestration API.

Error Response Format​

All error responses follow a consistent format:

{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error message",
    "timestamp": "2024-01-15T10:30:00Z",
    "details": {
      "field": "Additional error details",
      "suggestion": "Suggested action to resolve the error"
    }
  }
}

Common Error Codes​

HTTP Status Codes​

Status CodeDescriptionCommon Use Cases

Error Handling Best Practices​

Client-Side Error Handling​

async function createDAG(dagData) {
  try {
    const response = await fetch('/orchestration/api/v1/dags', {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(dagData)
    });

    if (!response.ok) {
      const errorData = await response.json();
      
      switch (errorData.error.code) {
        case 'DAG_ALREADY_RUNNING':
          // Handle DAG already running
          console.log('DAG is currently running, please wait');
          break;
        case 'INVALID_DAG_STRUCTURE':
          // Handle validation errors
          console.log('DAG structure is invalid:', errorData.error.details.validationErrors);
          break;
        case 'RATE_LIMIT_EXCEEDED':
          // Handle rate limiting
          const resetTime = new Date(errorData.error.details.resetTime);
          console.log(`Rate limit exceeded, reset at ${resetTime}`);
          break;
        default:
          // Handle other errors
          console.error('Unexpected error:', errorData.error.message);
      }
      
      throw new Error(errorData.error.message);
    }

    return await response.json();
  } catch (error) {
    console.error('Failed to create DAG:', error);
    throw error;
  }
}

Retry Logic​

async function retryOperation(operation, maxRetries = 3) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await operation();
    } catch (error) {
      if (error.error?.code === 'RATE_LIMIT_EXCEEDED' && attempt < maxRetries) {
        const resetTime = new Date(error.error.details.resetTime);
        const waitTime = resetTime.getTime() - Date.now();
        
        if (waitTime > 0) {
          console.log(`Rate limited, waiting ${waitTime}ms before retry`);
          await new Promise(resolve => setTimeout(resolve, waitTime));
        }
      } else if (error.error?.code === 'DAG_ALREADY_RUNNING' && attempt < maxRetries) {
        console.log('DAG is running, waiting before retry');
        await new Promise(resolve => setTimeout(resolve, 5000));
      } else {
        throw error;
      }
    }
  }
}

Error Recovery Strategies​

Error TypeRecovery Strategy
DAG_ALREADY_RUNNINGWait and retry, or cancel existing run
CIRCULAR_DEPENDENCYReview and fix DAG structure
INVALID_DAG_STRUCTUREValidate and correct DAG configuration
RATE_LIMIT_EXCEEDEDImplement exponential backoff
PIPELINE_NOT_FOUNDVerify pipeline exists and is accessible
VERSION_CONFLICTUse different version or auto-increment

Monitoring and Logging​

Error Logging​

function logError(error, context) {
  const errorLog = {
    timestamp: new Date().toISOString(),
    errorCode: error.error?.code,
    message: error.error?.message,
    context: context,
    details: error.error?.details,
    stack: error.stack
  };
  
  console.error('Orchestration API Error:', errorLog);
  // Send to monitoring service
  sendToMonitoringService(errorLog);
}
