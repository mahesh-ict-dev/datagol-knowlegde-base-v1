# Error Handling

This section describes the error handling patterns and common error responses for the Orchestration API.

## Error Response Format

All error responses follow a consistent format:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error message",
    "timestamp": "2024-01-15T10:30:00Z",
    "details": {
      "field": "Additional error details",
      "suggestion": "Suggested action to resolve the error"
    }
  }
}
```

## Common Error Codes

### HTTP Status Codes

| Status Code | Description | Common Use Cases |
|-------------|-------------|------------------|
| 400 | Bad Request | Invalid request parameters, malformed JSON |
| 401 | Unauthorized | Missing or invalid authentication token |
| 403 | Forbidden | Insufficient permissions for the operation |
| 404 | Not Found | Resource (DAG, node, edge, run) not found |
| 409 | Conflict | Resource conflict, DAG already running |
| 422 | Unprocessable Entity | Validation errors, invalid DAG structure |
| 429 | Too Many Requests | Rate limit exceeded |
| 500 | Internal Server Error | Server error, unexpected exception |

### Orchestration-Specific Error Codes

| Error Code | Description | HTTP Status |
|------------|-------------|-------------|
| `DAG_NOT_FOUND` | DAG with specified ID does not exist | 404 |
| `NODE_NOT_FOUND` | Node with specified ID does not exist | 404 |
| `EDGE_NOT_FOUND` | Edge with specified ID does not exist | 404 |
| `RUN_NOT_FOUND` | DAG run with specified ID does not exist | 404 |
| `SNAPSHOT_NOT_FOUND` | Snapshot with specified ID does not exist | 404 |
| `DAG_ALREADY_RUNNING` | Cannot start new run while DAG is running | 409 |
| `CIRCULAR_DEPENDENCY` | Edge creation would create circular dependency | 409 |
| `INVALID_DAG_STRUCTURE` | DAG structure validation failed | 422 |
| `INVALID_SCHEDULE` | Invalid scheduling configuration | 422 |
| `NODE_LIMIT_EXCEEDED` | Maximum number of nodes exceeded | 422 |
| `EDGE_LIMIT_EXCEEDED` | Maximum number of edges exceeded | 422 |
| `INVALID_PARAMETERS` | Invalid run parameters | 422 |
| `PIPELINE_NOT_FOUND` | Referenced pipeline does not exist | 404 |
| `PIPELINE_ACCESS_DENIED` | No access to referenced pipeline | 403 |
| `VERSION_CONFLICT` | Snapshot version already exists | 409 |
| `INVALID_RESTORE` | Cannot restore from invalid snapshot | 422 |

## Error Handling Best Practices

### Client-Side Error Handling

```javascript
async function createDAG(dagData) {
  try {
    const response = await fetch('/orchestration/api/v1/dags', {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(dagData)
    });

    if (!response.ok) {
      const errorData = await response.json();
      
      switch (errorData.error.code) {
        case 'DAG_ALREADY_RUNNING':
          // Handle DAG already running
          console.log('DAG is currently running, please wait');
          break;
        case 'INVALID_DAG_STRUCTURE':
          // Handle validation errors
          console.log('DAG structure is invalid:', errorData.error.details.validationErrors);
          break;
        case 'RATE_LIMIT_EXCEEDED':
          // Handle rate limiting
          const resetTime = new Date(errorData.error.details.resetTime);
          console.log(`Rate limit exceeded, reset at ${resetTime}`);
          break;
        default:
          // Handle other errors
          console.error('Unexpected error:', errorData.error.message);
      }
      
      throw new Error(errorData.error.message);
    }

    return await response.json();
  } catch (error) {
    console.error('Failed to create DAG:', error);
    throw error;
  }
}
```

### Retry Logic

```javascript
async function retryOperation(operation, maxRetries = 3) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await operation();
    } catch (error) {
      if (error.error?.code === 'RATE_LIMIT_EXCEEDED' && attempt < maxRetries) {
        const resetTime = new Date(error.error.details.resetTime);
        const waitTime = resetTime.getTime() - Date.now();
        
        if (waitTime > 0) {
          console.log(`Rate limited, waiting ${waitTime}ms before retry`);
          await new Promise(resolve => setTimeout(resolve, waitTime));
        }
      } else if (error.error?.code === 'DAG_ALREADY_RUNNING' && attempt < maxRetries) {
        console.log('DAG is running, waiting before retry');
        await new Promise(resolve => setTimeout(resolve, 5000));
      } else {
        throw error;
      }
    }
  }
}
```

### Error Recovery Strategies

| Error Type | Recovery Strategy |
|------------|-------------------|
| `DAG_ALREADY_RUNNING` | Wait and retry, or cancel existing run |
| `CIRCULAR_DEPENDENCY` | Review and fix DAG structure |
| `INVALID_DAG_STRUCTURE` | Validate and correct DAG configuration |
| `RATE_LIMIT_EXCEEDED` | Implement exponential backoff |
| `PIPELINE_NOT_FOUND` | Verify pipeline exists and is accessible |
| `VERSION_CONFLICT` | Use different version or auto-increment |

## Monitoring and Logging

### Error Logging

```javascript
function logError(error, context) {
  const errorLog = {
    timestamp: new Date().toISOString(),
    errorCode: error.error?.code,
    message: error.error?.message,
    context: context,
    details: error.error?.details,
    stack: error.stack
  };
  
  console.error('Orchestration API Error:', errorLog);
  // Send to monitoring service
  sendToMonitoringService(errorLog);
}
```
