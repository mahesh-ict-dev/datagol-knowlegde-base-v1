# Datasources API Documentation

## Overview

The Datasources API provides comprehensive functionality for managing data sources, tables, columns, queries, annotations, and related metadata. All APIs are currently available in version 1.

## Base URL Structure

```bash
dataSources/api/v1/     # Version 1 APIs
```

## Authentication

All Datasources APIs require JWT authentication via the `s_jwt` security requirement.

## 1. Core DataSource Management

### DataSource CRUD Operations
**Base Path**: `dataSources/api/v1/dataSources`

| Method | Endpoint | Description | Required Roles |
|--------|----------|-------------|----------------|
| `POST` | `/` | Create a new datasource | `ROLE_CREATE_LAKEHOUSE`, `ROLE_CREATE_DATASOURCE` |
| `GET` | `/` | Get all datasources | `ROLE_VIEW_LAKEHOUSE`, `ROLE_VIEW_DATASOURCE` |
| `GET` | `/{dataSourceId}` | Get datasource by ID | `ROLE_VIEW_LAKEHOUSE`, `ROLE_VIEW_DATASOURCE` |
| `PUT` | `/{dataSourceId}` | Update datasource | `ROLE_EDIT_LAKEHOUSE`, `ROLE_EDIT_DATASOURCE` |
| `DELETE` | `/{dataSourceId}` | Delete datasource | `ROLE_DELETE_LAKEHOUSE`, `ROLE_DELETE_DATASOURCE` |

#### Query Parameters
- `includeTables` (boolean, default: false) - Include table information
- `includeSchema` (boolean, default: false) - Include schema information

### DataSource Relationships
| Method | Endpoint | Description | Required Roles |
|--------|----------|-------------|----------------|
| `GET` | `/getDataSourcesRelationships` | Get datasource relationships | `ROLE_VIEW_LAKEHOUSE`, `ROLE_VIEW_DATASOURCE` |

### Schema Synchronization
| Method | Endpoint | Description | Required Roles |
|--------|----------|-------------|----------------|
| `GET` | `/{dataSourceId}/syncSchema` | Sync datasource schema | `ROLE_VIEW_LAKEHOUSE`, `ROLE_VIEW_DATASOURCE` |
| `GET` | `/{dataSourceId}/getSyncSchemaStatus` | Get sync schema status | `ROLE_VIEW_LAKEHOUSE`, `ROLE_VIEW_DATASOURCE` |

## Common Features

### Authentication
All APIs require JWT authentication with the `s_jwt` security requirement.

### Role-Based Access Control
- `ROLE_CREATE_LAKEHOUSE` / `ROLE_CREATE_DATASOURCE` - Create operations
- `ROLE_VIEW_LAKEHOUSE` / `ROLE_VIEW_DATASOURCE` - Read operations  
- `ROLE_EDIT_LAKEHOUSE` / `ROLE_EDIT_DATASOURCE` - Update operations
- `ROLE_DELETE_LAKEHOUSE` / `ROLE_DELETE_DATASOURCE` - Delete operations

### Error Handling
- Standard HTTP status codes
- Consistent error response format
- Detailed error messages for debugging

### Request/Response Format
- JSON request/response bodies
- Consistent DTO structures
- Proper validation annotations

### File Upload
- Multipart file upload support
- Various file format support (CSV, Excel, etc.)
- File validation and processing

### Pagination
- Support for paginated responses
- Page number and size parameters
- Consistent pagination structure

## Data Types

### DataSource Types
- `SQL` - SQL databases (PostgreSQL, MySQL, etc.)
- `S3` - Amazon S3 storage
- `AZURE` - Azure Blob Storage
- `CSV` - CSV files
- `PARQUET` - Parquet files
- `JSON` - JSON files

### Storage Types
- `S3` - Amazon S3
- `AZURE` - Azure Blob Storage

### Request Status
- `INITIATED` - Request started
- `IN_PROGRESS` - Request in progress
- `COMPLETED` - Request completed
- `FAILED` - Request failed
