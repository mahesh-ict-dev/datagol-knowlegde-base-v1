# Error Handling

This page describes error handling patterns and common error scenarios for the Datasources API.

## HTTP Status Codes

The Datasources API uses standard HTTP status codes to indicate the success or failure of requests.

### Success Codes

- `200 OK` - Request completed successfully
- `201 Created` - Resource created successfully
- `204 No Content` - Request completed successfully, no content to return

### Client Error Codes

- `400 Bad Request` - Invalid request syntax or parameters
- `401 Unauthorized` - Authentication required or failed
- `403 Forbidden` - Access denied due to insufficient permissions
- `404 Not Found` - Resource not found
- `409 Conflict` - Resource conflict (e.g., duplicate name)
- `422 Unprocessable Entity` - Request validation failed

### Server Error Codes

- `500 Internal Server Error` - Unexpected server error
- `502 Bad Gateway` - Upstream service unavailable
- `503 Service Unavailable` - Service temporarily unavailable

## Error Response Format

All error responses follow a consistent format:

```json
{
  "error": "string",
  "message": "string",
  "code": "string (optional)",
  "details": "object (optional)",
  "timestamp": "string (ISO 8601)"
}
```

### Error Response Fields

- `error` - Error type or category
- `message` - Human-readable error description
- `code` - Application-specific error code (optional)
- `details` - Additional error details (optional)
- `timestamp` - When the error occurred

## Common Error Scenarios

### Authentication Errors

#### 401 Unauthorized
```json
{
  "error": "UNAUTHORIZED",
  "message": "Authentication required",
  "code": "AUTH_REQUIRED",
  "timestamp": "2024-01-15T10:30:00.000Z"
}
```

**Causes:**
- Missing JWT token
- Invalid JWT token
- Expired JWT token

**Solutions:**
- Include valid JWT token in Authorization header
- Refresh JWT token if expired
- Verify token format: `Bearer <token>`

#### 403 Forbidden
```json
{
  "error": "FORBIDDEN",
  "message": "Insufficient permissions to access this resource",
  "code": "INSUFFICIENT_PERMISSIONS",
  "details": {
    "requiredRole": "ROLE_VIEW_DATASOURCE",
    "userRoles": ["ROLE_VIEW_LAKEHOUSE"]
  },
  "timestamp": "2024-01-15T10:30:00.000Z"
}
```

**Causes:**
- User lacks required role permissions
- Resource access restricted to specific users/workspaces

**Solutions:**
- Request appropriate role assignment
- Verify workspace membership
- Check resource ownership

### Validation Errors

#### 400 Bad Request
```json
{
  "error": "VALIDATION_ERROR",
  "message": "Request validation failed",
  "code": "INVALID_REQUEST",
  "details": {
    "field": "name",
    "value": "",
    "constraint": "must not be empty"
  },
  "timestamp": "2024-01-15T10:30:00.000Z"
}
```

**Common Validation Errors:**
- Missing required fields
- Invalid field values
- Field length constraints
- Invalid data types

**Solutions:**
- Review request payload
- Check field requirements
- Validate data types and formats

#### 422 Unprocessable Entity
```json
{
  "error": "BUSINESS_RULE_VIOLATION",
  "message": "DataSource name must be unique within workspace",
  "code": "DUPLICATE_NAME",
  "details": {
    "field": "name",
    "value": "My Database",
    "existingId": "ds-123"
  },
  "timestamp": "2024-01-15T10:30:00.000Z"
}
```

**Causes:**
- Business rule violations
- Data integrity constraints
- Duplicate resource names

**Solutions:**
- Use unique names
- Check existing resources
- Follow business rules

### Resource Errors

#### 404 Not Found
```json
{
  "error": "RESOURCE_NOT_FOUND",
  "message": "DataSource with ID 'ds-456' not found",
  "code": "DATASOURCE_NOT_FOUND",
  "details": {
    "resourceType": "DataSource",
    "resourceId": "ds-456"
  },
  "timestamp": "2024-01-15T10:30:00.000Z"

```

**Causes:**
- Resource doesn't exist
- Resource was deleted
- Invalid resource ID

**Solutions:**
- Verify resource ID
- Check if resource exists
- Use correct resource identifiers

### Server Errors

#### 500 Internal Server Error
```json
{
  "error": "INTERNAL_SERVER_ERROR",
  "message": "An unexpected error occurred",
  "code": "DATABASE_CONNECTION_FAILED",
  "timestamp": "2024-01-15T10:30:00.000Z"
}
```

**Causes:**
- Database connection issues
- External service failures
- System configuration problems

**Solutions:**
- Retry request after delay
- Check system status
- Contact support if persistent

## Error Handling Best Practices

### Client-Side Error Handling

#### Python Example
```python
import requests
from typing import Optional, Dict, Any

class DataGOLAPIError(Exception):
    def __init__(self, message: str, status_code: int, error_code: Optional[str] = None):
        self.message = message
        self.status_code = status_code
        self.error_code = error_code
        super().__init__(self.message)

def handle_api_response(response: requests.Response) -> Dict[str, Any]:
    """Handle API response and raise appropriate exceptions"""
    if response.ok:
        return response.json()
    
    try:
        error_data = response.json()
        error_message = error_data.get('message', f'HTTP {response.status_code}')
        error_code = error_data.get('code')
    except ValueError:
        error_message = f'HTTP {response.status_code}'
        error_code = None
    
    raise DataGOLAPIError(error_message, response.status_code, error_code)

def safe_api_call(func):
    """Decorator for safe API calls with error handling"""
    def wrapper(*args, **kwargs):
        try:
            return func(*args, **kwargs)
        except DataGOLAPIError as e:
            if e.status_code == 401:
                print("Authentication failed. Please check your JWT token.")
            elif e.status_code == 403:
                print("Access denied. Check your permissions.")
            elif e.status_code == 404:
                print("Resource not found.")
            elif e.status_code == 409:
                print("Resource conflict:", e.message)
            elif e.status_code >= 500:
                print("Server error. Please try again later.")
            else:
                print(f"API Error: {e.message}")
            raise
        except requests.exceptions.RequestException as e:
            print(f"Network error: {e}")
            raise
    return wrapper
```

#### JavaScript Example

```javascript
class DataGOLAPIError extends Error {
  constructor(message, statusCode, errorCode = null) {
    super(message);
    this.name = 'DataGOLAPIError';
    this.statusCode = statusCode;
    this.errorCode = errorCode;
  }
}

async function handleAPIResponse(response) {
  if (response.ok) {
    return response.json();
  }
  
  let errorData;
  try {
    errorData = await response.json();
  } catch {
    errorData = {};
  }
  
  const message = errorData.message || `HTTP ${response.status}`;
  const errorCode = errorData.code;
  
  throw new DataGOLAPIError(message, response.status, errorCode);
}

async function safeAPICall(apiCall) {
  try {
    return await apiCall();
  } catch (error) {
    if (error instanceof DataGOLAPIError) {
      switch (error.statusCode) {
        case 401:
          console.error('Authentication failed. Please check your JWT token.');
          break;
        case 403:
          console.error('Access denied. Check your permissions.');
          break;
        case 404:
          console.error('Resource not found.');
          break;
        case 409:
          console.error('Resource conflict:', error.message);
          break;
        default:
          if (error.statusCode >= 500) {
            console.error('Server error. Please try again later.');
          } else {
            console.error('API Error:', error.message);
          }
      }
    } else {
      console.error('Network error:', error.message);
    }
    throw error;
  }
}
```

### Retry Logic

```python
import time
from functools import wraps

def retry_on_error(max_retries=3, delay=1, backoff=2):
    """Retry decorator for transient errors"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_exception = None
            
            for attempt in range(max_retries + 1):
                try:
                    return func(*args, **kwargs)
                except DataGOLAPIError as e:
                    last_exception = e
                    
                    # Don't retry on client errors (4xx)
                    if 400 <= e.status_code < 500:
                        raise
                    
                    # Retry on server errors (5xx)
                    if attempt < max_retries:
                        sleep_time = delay * (backoff ** attempt)
                        print(f"Attempt {attempt + 1} failed. Retrying in {sleep_time}s...")
                        time.sleep(sleep_time)
                    else:
                        print(f"All {max_retries + 1} attempts failed.")
                        raise
                        
            raise last_exception
        return wrapper
    return decorator

# Usage
@retry_on_error(max_retries=3, delay=1)
def create_datasource_with_retry(self, name, type, properties):
    return self.create_datasource(name, type, properties)
```

### Logging and Monitoring

```python
import logging
from datetime import datetime

# Configure logging
logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

def log_api_call(func):
    """Decorator to log API calls and errors"""
    def wrapper(*args, **kwargs):
        start_time = datetime.now()
        
        try:
            result = func(*args, **kwargs)
            duration = (datetime.now() - start_time).total_seconds()
            logger.info(f"API call {func.__name__} completed in {duration:.2f}s")
            return result
        except DataGOLAPIError as e:
            duration = (datetime.now() - start_time).total_seconds()
            logger.error(f"API call {func.__name__} failed after {duration:.2f}s: {e.status_code} - {e.message}")
            raise
        except Exception as e:
            duration = (datetime.now() - start_time).total_seconds()
            logger.error(f"API call {func.__name__} failed after {duration:.2f}s: {str(e)}")
            raise
    return wrapper
```

## Troubleshooting Guide

### Common Issues and Solutions

#### 1. Authentication Issues
**Problem:** Getting 401 Unauthorized errors
**Solutions:**
- Verify JWT token is valid and not expired
- Check token format: `Bearer <token>`
- Ensure token has required scopes

#### 2. Permission Issues
**Problem:** Getting 403 Forbidden errors
**Solutions:**
- Verify user has required roles
- Check workspace membership
- Contact administrator for role assignment

#### 3. Resource Not Found
**Problem:** Getting 404 Not Found errors
**Solutions:**
- Verify resource ID is correct
- Check if resource exists in workspace
- Ensure resource hasn't been deleted

#### 4. Validation Errors
**Problem:** Getting 400 Bad Request errors
**Solutions:**
- Review request payload structure
- Check required fields are present
- Validate data types and formats

#### 5. Server Errors
**Problem:** Getting 500 Internal Server Error
**Solutions:**
- Retry request after delay
- Check system status page
- Contact support if persistent

### Debugging Tips

1. **Enable Detailed Logging**
   - Log request/response details
   - Include error codes and messages
   - Track request timing

2. **Validate Request Data**
   - Check payload structure
   - Verify data types
   - Test with minimal payload

3. **Test with Different Tools**
   - Use curl for command-line testing
   - Try Postman for GUI testing
   - Compare with working examples

4. **Check API Documentation**
   - Verify endpoint URLs
   - Check required parameters
   - Review data models

5. **Monitor Rate Limits**
   - Check for rate limiting headers
   - Implement exponential backoff
   - Respect API usage limits
