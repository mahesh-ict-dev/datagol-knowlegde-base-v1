# Data Models

This page describes the data models and schemas used in the Datasources API.

## DataSource Model

```json
{
  "id": "string",
  "name": "string",
  "type": "string",
  "properties": "object",
  "createdAt": "string (ISO 8601)",
  "updatedAt": "string (ISO 8601)",
  "status": "string",
  "tables": "array (optional)",
  "schemas": "array (optional)"
}
```

### DataSource Types

- `SQL` - SQL databases (PostgreSQL, MySQL, etc.)
- `S3` - Amazon S3 storage
- `AZURE` - Azure Blob Storage
- `CSV` - CSV files
- `PARQUET` - Parquet files
- `JSON` - JSON files

## Status Values

### Request Status
- `INITIATED` - Request started
- `IN_PROGRESS` - Request in progress
- `COMPLETED` - Request completed
- `FAILED` - Request failed

### DataSource Status
- `ACTIVE` - DataSource is active and accessible
- `INACTIVE` - DataSource is inactive
- `ERROR` - DataSource has errors
- `SYNCING` - Schema synchronization in progress

### Schema Status
- `VALID` - Schema is valid
- `INVALID` - Schema has validation errors
- `SYNCING` - Schema synchronization in progress

## Common Fields

### Timestamps
All timestamp fields follow ISO 8601 format: `YYYY-MM-DDTHH:mm:ss.sssZ`

### IDs
All ID fields are strings and are generated by the system.

### Optional Fields
Fields marked as optional may be `null` or omitted from the response.

### Arrays
Array fields may be empty (`[]`) when no items exist.

## Validation Rules

### DataSource Name
- Required field
- Maximum 255 characters
- Must be unique within the workspace
- Alphanumeric characters, spaces, hyphens, and underscores only

### SQL Query
- Required field for queries
- Maximum 10,000 characters
- Must be valid SQL syntax for the target data provider

### File Upload
- Maximum file size: 100MB
- Supported formats: CSV, JSON, Parquet, Excel
- File name must be unique within the table

### Pagination
- Default page size: 20
- Maximum page size: 100
- Page numbers start from 0
